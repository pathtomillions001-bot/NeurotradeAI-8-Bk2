# Railway deployment

This repository deploys as one Railway web service plus a Railway PostgreSQL
service. The web service builds the Vite frontend first, then bundles the
Express API. Express serves the frontend in production so the browser keeps a
single origin for `/api`, OAuth, HttpOnly session cookies, and SSE.

## Web service

- Root directory: `/`
- Build command: `pnpm run build:railway`
- Start command: `pnpm run start:railway`
- Healthcheck path: `/api/healthz`
- `PORT`: leave unset; Railway injects it

`railway.json` contains the same build, start, database pre-deploy, healthcheck,
and restart settings for Railway deployments.

## PostgreSQL

Create a PostgreSQL service in the same Railway project and add this reference
to the web service variables:

```text
DATABASE_URL=${{Postgres.DATABASE_URL}}
```

Replace `Postgres` with the exact name of the database service if it is named
differently. The pre-deploy command applies the Drizzle schema from the
repository root.

## Web service variables

```text
NODE_ENV=production
LIVE_TRADING_ENABLED=false
DERIV_APP_ID=<the alphanumeric ID from the Deriv app dashboard>
SESSION_COOKIE_SECRET=<a long random value>
DATABASE_URL=${{Postgres.DATABASE_URL}}
LOG_LEVEL=info
```

Do not set `API_PORT`; the server uses Railway's injected `PORT` when
`API_PORT` is absent. `LIVE_TRADING_ENABLED=false` is also the application
fail-safe default. Change it to `true` only after deployment and demo-account
smoke tests are complete.

## Deriv OAuth

After the Railway domain is generated, register this exact callback URL in the
Deriv application dashboard:

```text
https://<generated-domain>.up.railway.app/connect
```

The path, scheme, host, and trailing slash must match the value generated by
the frontend.

## Smoke-test order

1. Open the generated Railway domain.
2. Confirm `/api/healthz` returns a healthy response.
3. Confirm the sidebar says `Simulation only — live trading disabled`.
4. Test markets, settings, analytics, SSE updates, and the journal.
5. Use a Deriv demo account only if account connectivity is required.
6. Enable live trading only by explicitly changing `LIVE_TRADING_ENABLED` to
   `true` after the checks above.
